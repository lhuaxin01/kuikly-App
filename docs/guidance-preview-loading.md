# 导航跟随、返回预览与加载状态

## 原因和修改

MapTemplate 的实时导航使用高德导航视图管理锁车和近景镜头。鸿蒙当前使用普通地图视图叠加 Kuikly 界面，原实现只把相机移动到定位点，缩放和方向不能呈现相同的导航细节。此前“退出”还复用了清空路线的停止命令，因此无法返回原路线预览。异步命令发出到平台状态回传之间缺少加载态，也允许重复点击。

本次保持共享业务与平台 SDK 分层，补齐三条流程：

1. **实时跟随**：鸿蒙适配器根据导航定位更新当前位置标记和镜头。驾车缩放 17.5、俯角 45°；骑行缩放 17.7、俯角 35°；步行缩放 18、俯角 0°。实时导航前进方向朝上，低速时过滤方向抖动，镜头动画为 450 毫秒。“路线全览”恢复北向上和俯视，展示整条路线；“跟随当前位置”立即回到最近导航定位，无需等待下一次定位。Kuikly 导航面板收起预览信息，显示当前位置道路、距下一导航点距离、剩余距离与时间。
2. **返回路线预览**：新增 `exitGuidance` 命令，停止导航、GPS 和播报，移除旧监听，保留地图、路线覆盖物、已选路线和目的地；状态回到 `ROUTE_READY`，并恢复全览。导航页退出按钮、SDK 退出事件、导航中的首次系统返回使用该命令。用户随后可重新选择“开始导航”或“模拟导航”。普通停止、取消处理、任务替换仍使用原有完整停止流程。真实定位过期时再次真实导航会先重新定位、算路，完成后由用户确认启动。
3. **加载与防重复操作**：`NavigationStore` 汇总后端请求、定位、算路及启动状态；`pendingCommand` 补上桥接回调前的空档，`preparingRoute` 覆盖新任务替换旧导航时的准备阶段。输入栏位置显示一行小转圈、短提示和“取消”，不再使用全屏灰色遮罩；地图可以拖动和缩放，选点、重复提交、出行方式及会话切换仍受状态保护。错误、取消、候选确认或路线就绪后恢复输入；停止时取消后端待处理请求，旧回调不能重新打开导航。

## 方向摆正与加载简化的进一步调整

跟随导航时采用“前进方向朝上”，路线预览采用“北向上”。静止时 GPS 不能可靠反映手机朝向，保留稳定方向，避免因首个不可靠的方位值而转动地图。启动时优先使用近期可靠航向；缺少航向且当前位置在路线起点附近时，可用路线起始段方向辅助摆正，之后由可靠导航定位接管。

原实现每次启动将航向清零，首个方位值没有速度限制，之后每次仅混合新航向的一半，可能出现起步转向及转弯后方向滞后。修正后按 GPS 定位类型、精度、移动速度判断航向可信度；忽略小角度抖动，用地图动画直接过渡到新的可靠航向。跟随期间锁定手动旋转和倾斜，全览及退出后恢复手势。

高德 [AMapNaviLocation 官方说明](https://a.amap.com/lbs-dev-yuntu/static/reference/harmonyosnext-sdk/navi/docs/classes/api_navi_model_AMapNaviLocation.AMapNaviLocation.html) 明确速度单位为 km/h；代码按该单位区分步行与驾车/骑行的低速阈值。本地适配基于安装的 11.2 SDK 接口。当前标记是位置图钉，不将其当作车头箭头旋转，也不使用手机磁力计推测行进方向。

加载提示保留输入栏原有位置和高度，原输入框仍挂载并保留内容，处理时暂时隐藏；隐藏导航面板里重复的过程文案，只显示一条当前阶段提示。输入栏随宿主键盘避让区域移动。会话、重试地图等之前依赖遮罩保护的入口补齐状态判断，正常错误内容在处理结束后仍然显示。

## 代码职责

| 层级 | 文件 | 职责 |
| --- | --- | --- |
| 共享页面 | `NavigationPage.kt` | 精简导航面板、全览/跟随、退出按钮、输入栏进度 |
| 共享状态 | `NavigationStore.kt` | 加载阶段、命令等待、重复操作保护、预览恢复 |
| 共享端口/桥接 | `NavigationPort.kt`、`NavigationModule.kt` | 传递 `exitGuidance`，不引用 SDK |
| 鸿蒙会话/宿主 | `HarmonyNavigationSession.ets`、`NavigationHostPage.ets` | 命令分发、系统返回处理 |
| 导航状态机 | `NavigationController.ts` | 保留路线的退出状态转换、资源停止失败处理 |
| SDK 适配器 | `AmapNavigationEngine.ets` | 相机、路线保留、监听代次隔离和资源管理 |

模拟位置只用于导航展示，不覆盖真实定位；退出演示后恢复最近真实位置。按本机安装的高德 HarmonyOS 11.2 SDK 接口约定，`startNavi(GPS)` 会自动重新启动卫星定位。清理失败会进入明确错误状态，避免把未停止的引擎当成可启动的预览。

本次不修改 navi-claw 协议、后端或 Key 配置。采用 MapTemplate 的导航/预览模式和处理状态思路；退出时保留路线覆盖物，是按本次需求在鸿蒙端补充的行为。

真机仍需验收：

1. 驾车、步行、骑行分别启动真实/模拟导航，观察道路细节、当前位置和前进方向；切到全览后应保持全览，再点跟随应立即回到当前位置。
2. 导航中点“退出导航”或系统返回，确认目的地和路线保留，且可再次开始真实导航或模拟导航。
3. 输入目的地后连续点击发送、长按地图、出行方式和底部 Tab，确认仅处理一次请求且不改变目的地；地图拖动、缩放仍可用。候选出现后可选地点，算路完成后可启动；超时、失败和取消后应恢复操作。
4. 退出演示后开启真实导航，确认不沿用模拟位置；等待定位过期后重新启动，确认先取得真实位置并重算。
5. 小屏、键盘弹出时，确认加载提示、输入框、导航面板及地图的层级和可见范围。
6. 从东/西/南向的路线起步，检查前进方向朝上；停步或等红灯时不应跟随低速漂移旋转，移动转弯后应及时摆正。切到全览应北向上，再点跟随应恢复导航航向。

本机编译和自动测试不能替代道路环境、定位质量、镜头观感以及原生地图叠层的真机验证。
