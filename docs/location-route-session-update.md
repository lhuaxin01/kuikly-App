# 定位、路线与会话详情更新（2026-09-28）

## 本次修复

此前虽然已有高德定位与算路 API，页面和状态流仍存在断点：加载地图或定位期间到达的导航任务被当成不可编辑状态拒绝；清除旧路线时的同步状态回调可能触发旧草稿；位置过期后只重定位，不继续原算路请求。页面也没有展示原生状态消息，导航按钮区域与底部搜索栏重叠。

本次由共享 `NavigationStore` 保存待规划任务，由鸿蒙 `NavigationController` 管理实际定位、算路、导航回调及资源释放。地图就绪后自动请求精确位置；定位成功后执行待规划任务；位置过期时重新定位并保留目的地、途经点与出行方式。已有路线时切换驾车、步行、骑行会重新生成预览。开始导航仍由用户点击确认。点击“当前位置”会将地图重新移到设备位置，后续位置更新不会抢走路线总览视角。

导航操作面板移到搜索栏上方，显示当前位置坐标、处理状态、错误原因、目的地及路线距离/时长。定位仍依赖系统精确定位权限和位置服务，失败不会回退到模拟位置。

## MapTemplate 会话复用

- 参照 `fragment_my.xml`、`fragment_map.xml`、`ConversationMessageAdapter.java`：保留“内容/切换、刷新、关闭”，会话列表与详情使用滚动容器；用户消息靠右、蓝色气泡，助手消息靠左、浅色气泡。去除末五条及每条五行的截断。
- 参照 `SessionApiClient.java`：新增共享 `SessionPresentation`，按轮次合并 `channel_inbound / structured_request / user_message`，优先展示最终 `channel_outbound`，把路线、候选地点、错误转为可读内容，过滤原始 JSON 和内部工具事件。即时回复与历史使用同一规则。
- 新增共享 `SessionCoordinator`：创建会话先走 HTTP `sessions.create`，再执行 WebSocket `channel.attach`，绑定成功后才激活会话并更新导航请求上下文。绑定失败保留原会话，迟到的历史/列表回调不能覆盖新会话或新账号。
- 显式会话切换使用 `resume_only`，校验返回的会话 ID；定位/算路能力上报统一为最多 3 个途经点。沿用 navi-claw 现有接口，本次无需更改后端协议。

## 验证与手动验收

共享层回归覆盖定位前任务、同步回调重入、出行方式重算、会话事件去重、会话创建与频道绑定顺序、失败恢复和迟到响应；原生控制器回归覆盖过期位置续算路、模式传递、导航进度及资源释放。

本轮验证结果：共享 Kotlin 59 项测试通过，导航控制器 25 项测试通过；Kotlin Native、ArkTS 与签名 HAP 构建成功，页面结构、页面注册及 HAP 资源静态检查通过。静态检查不等同于真机视觉验收，本轮未在设备上实测 GPS、在线算路和页面遮挡。

在项目根目录手动构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-harmony.ps1
```

输出：`artifacts/harmony/navi-harmony-navigation-signed.hap`，校验文件为同路径加 `.sha256`。构建会先重新生成共享 Kotlin Native 库，再打包鸿蒙代码。

建议使用新 HAP 按以下顺序验收：

1. 同意地图服务并授权精确定位，确认定位状态、坐标和地图当前位置标记；移动地图后点击“当前位置”确认回中。
2. 输入附近目的地，在定位等待期间提交一次请求，确认位置就绪后仍能生成路线；分别切换驾车、步行、骑行，确认重新算路及距离/时长。
3. 点击开始导航或模拟导航，检查进度更新；停止后确认原生资源释放。
4. 在“我的”新建命名会话、输入导航内容；切换历史会话，再回首页继续对话，确认请求没有绑定错误。
5. 分别检查首页会话浮层和“我的”详情：左右气泡、长文本滚动、无重复轮次或原始 JSON；刷新详情应重新获取历史。
6. 在长列表、长对话与小屏设备检查搜索栏、导航按钮和底部 Tab 不互相遮挡。

限制：当前位置目前展示坐标及地图标记，尚未新增反向地理编码地址。算路默认从设备实时位置出发；本次没有加入任意指定起点预览。历史仍沿用后端最近 50 条事件接口，未增加历史分页。编译与自动化测试不能替代 GPS、SDK 在线服务与真机视觉验收。
